## 1. ЦЕЛЬ ПРОЕКТА

Создать **универсального агента-трейдера SmartExecutor**, который:

- Торгует на биржах через API (OKX, Bybit).
- Анализирует рынок через графики, объёмы, контекст.
- **Понимает причины** движения цены (новости, листинги, геополитика, манипуляции).
- **Учится** на сделках, ведёт библиотеку уроков.
- **Разборчив** в информационном шуме.
- Работает в трёх режимах: **Lite / Pro / Scalpel**.
- Отдаётся в аренду — **двойной контур документации**.

**Архитектор** — задаёт цели, принимает решения.
**Ассистент** — предлагает, разбирает, фиксирует.

### 1.1. Ключевая фишка

**Арбитраж с контекстом.** Не только «цена», а «цена + контекст»:
- события, новости;
- тренд, волатильность;
- confidence (согласие модулей);
- дисциплина (PsychologyGuard);
- объяснения (K-026).

**Это — преимущество перед обычными арбитраж-ботами.**

## 2. АРХИТЕКТУРА

### 2.1. Три уровня

| Уровень | Роль | Знает | Не знает |
|---------|------|-------|----------|
| **Ядро** (`kernel.py`) | Воля | Каноны, режимы, состояние | Имён модулей |
| **Диспетчер** (`dispatcher.py`) | Руки | Реестр, порядок, критичность | Канонов торговли |
| **Модуль** (`submodules/`) | Работа | Только свою задачу | Кто вызвал, что было до |

### 2.2. Поток

[ЯДРО] — intent — ↓
[ДИСПЕТЧЕР] — вызывает по очереди — ↓
[MODULE 1] [MODULE 2] [MODULE 3] ...
[ДИСПЕТЧЕР] — собирает, валидирует, логирует — ↓
[ЯДРО] — принимает решение


**Ядро не знает имён.** Диспетчер по `registry.json` знает, кого звать на `intent`.

### 2.3. Intent-модель

**Ядро говорит `intent` (что делать), диспетчер знает `маппинг` (кого звать).**

Примеры intent'ов:
- `prepare_data` → LevelBuilder
- `interpret_data` → TraderSense
- `evaluate_market` → InfoSense, TrendAnalyzer, Scanner
- `compare_outputs` → Methodist
- `check_signal` → ContextGate, RiskManager, PsychologyGuard
- `execute_trade` → StrategyPool, OKXConnector, PositionManager
- `analyze_trade` → TradeAnalyzer
- `audit_system` → Supervisor
- `verify_fact` → HallucinationGuard
- `store_confidence` → Архивариус

**Маппинг — в `core/registry.json`.**

### 2.4. Профили торговли (K-020)

**6 профилей:**
- `spot_long`
- `spot_short`
- `futures_long`
- `futures_short`
- `arbitrage_cross`
- `arbitrage_basis`

**Один профиль за раз** (K-021). Переключение — после закрытия позиций.

### 2.5. Объяснимость (K-026)

**Каждое решение — с объяснением.** Не лог. Лог — для отладки. Объяснение — для понимания.

**Это — уникальность проекта.**
